# CSV 三方合并工具（Base / Local / Remote）

一个完全本地运行的三方 CSV 合并网页：上传**基准、本地、远端**三份 UTF-8 CSV，
按共同的唯一键列做三方比对，自动合并不冲突的改动，把真正的冲突留给人工裁决，
最后导出沿用**基准表头顺序**的合并 CSV，并可生成逐格标注取值来源与原文件行号的
**合并结果来源账本**（页面展示 + JSON 下载）；如果结果承载父子层级，还可以选择父键列做
**父子层级核验**（缺失父项 / 循环检测，页面展示 + JSON 下载，只提示不改导出），
并在层级有效时生成**父子数据导入顺序**（父先子后稳定排序，页面展示键序 +
顺序 CSV 下载；存在缺失父项 / 循环时阻止顺序导出）。
在某一轮里裁决过的冲突还可以下载为**跨轮冲突裁决方案**（JSON），重新上传并比对后导入，
服务端按唯一键与三方原值逐行核对，只套用完全相同的冲突行，已手动处理的行整行跳过。
冲突全部裁决后还可以做**疑似唯一键变更核对**：从本轮基准与最终结果提取消失键与新增键
（两组各限 12 个），按自选的非键比较列与差异上限求允许交叉的一对一最优配对，
并对每个消失键列出所有最优方案中可能对应的新键——一致指向同一新键的标为稳定候选
（只是核对线索，不能认定为真实改名），页面展示最优配对数、总代价与候选代价，可下载 JSON。
冲突全部裁决后还可以做**最小决定列发现**：选择一个非键目标列和 1～10 个互异候选列
（不能含目标列或唯一键列），服务端在最终保留行（最多 300 行）上枚举所有成立且任何
真子集均不成立的候选列组合，每个非空组合附逐列移除的失效证明行对，无组合时给出
全候选列相同而目标不同的反例，页面按列数 / 基准表头列序展示并可下载 JSON
（结论仅适用于当前数据）。
冲突全部裁决后还可以做**合并金额尾差分摊**：选择互异的分组列与金额列，
金额以元计、只接受非负无指数最多四位小数的十进制字符串（非法值指出最终 CSV
行号并拒绝整次计算），各组精确求和后四舍五入到分，每行先向下取整到分，再把
差额按不足一分的余数降序、同余数按最终行序逐分分配，页面展示每组总额与逐行
分摊额，可下载按原行序追加「分摊金额」列的 CSV（原表头已有同名列明确报错，
无行时只输出新表头）。

- 后端：Node.js + Express
- 前端：原生 HTML / CSS / JavaScript（无框架、无构建步骤）
- 无任何第三方服务、无数据库、无外发请求；文件只在你的浏览器和本机容器之间传输

## 一条命令启动

需要本机已安装 Docker（含 Compose 插件）。

```bash
docker compose up --build
```

启动后用浏览器打开：

> **http://localhost:3000**

停止：在终端按 `Ctrl+C`，或另开终端执行 `docker compose down`。

端口被占用时，修改 `docker-compose.yml` 里的 `ports`（例如 `"8080:3000"`），
再访问 http://localhost:8080 。

### 不想用 Docker？

```bash
npm install
npm start
# 同样访问 http://localhost:3000
```

## 使用步骤

1. **上传文件**：分别选择基准、本地、远端三份 CSV（UTF-8 编码，可带 BOM）。
   也可以点击「载入示例数据」立即体验全部场景。
2. **选择唯一键列**：表头三份必须完全一致（列数、列名、顺序都一致），
   从下拉框中选择能唯一标识每行的列（如 `id`）。
3. **审查与解决冲突**：
   - 页面按行展示同一键在**基准 / 本地 / 远端**中的值，并标注来源文件与行号；
   - 顶部统计自动修改、自动新增、自动删除和冲突数量，可按状态筛选；
   - **行级冲突**：选择「保留行」或「删除行」；
   - **单元格冲突**：选择「取本地」「取远端」，或「手填」自定义值；
   - 右上角徽标实时显示剩余未解决冲突数，**未全部解决时导出按钮禁用**，
     即使绕过前端，服务端也会再次校验并拒绝导出（HTTP 409）。
3.1. **跨轮复用裁决（可选）**：
   - 冲突全部裁决后（本轮存在冲突行时），在第 3 区点击「下载裁决方案 JSON」，
     得到 `conflict-plan.json`：逐行记录唯一键列、表头、该行在**基准 / 本地 / 远端**
     的存在状态与各列原值、冲突类型和裁决（含手填值）；**不含 roundId、不含原文件行号**；
   - 之后任意一轮（甚至重启服务后）重新上传三份 CSV 并选择键列完成比对，点
     「导入裁决方案…」选择该 JSON，服务端用**本轮模型**按唯一键逐行核对，
     只有**键列与表头一致、三方原值及冲突类型完全相同**的行才整行套用；
     行序和原文件行号变化不影响匹配；
   - **当前行已有任一裁决（行级去留或任意单元格）时整行跳过**，保留你的人工操作；
   - 页面分别列出**已套用**和**跳过**的行及原因（键不存在 / 本轮不是冲突行 /
     已存在裁决 / 存在状态不同 / 原值不同 / 冲突类型不同）；
   - 方案格式错误、键列或表头不一致时服务端返回 400 且**不改动任何裁决**；
     未匹配上的冲突继续在表格中手动解决。套用后的裁决即本轮裁决，
     CSV 导出、来源账本、层级核验都读取它。
4. **查看来源账本**：冲突全部裁决后，页面第 4 区自动生成**合并结果来源账本**——
   按最终 CSV 行序列出每个保留键各列的最终值、取值来源（基准 / 本地 / 远端 /
   两侧相同 / 人工填写）和原文件行号；被删除的键不混入输出行，单独列出删除原因。
   每次改动裁决后账本都会重新生成；有未决冲突时服务端拒绝生成完整账本（HTTP 409）。
   点击「下载 JSON 账本」可保存 `merge-ledger.json` 用于存档或复核。
5. **父子层级核验（可选）**：如果合并结果承载父子层级（分类、组织、菜单等），
   在第 5 区从表头中选择**父键列**（唯一键列不可选）。冲突全部裁决后，
   服务端按最终保留行以最终唯一键建立索引自动核验：**空父键视为根**；
   父键指向不存在或已删除的键记**缺失父项**；父键指向自身或相互成环的环上成员记
   **循环**（仅仅指向环的行不报）。问题按最终 CSV 行序列出问题键、父键、类型与
   输出行号；每次改动裁决后自动重新核验，可下载 JSON 结果。
   核验只提示问题，不改变导出的 CSV。
6. **父子数据导入顺序（可选）**：要把合并结果导入要求父行先于子行写入的下游系统时，
   在第 5 区选好父键列后，第 6 区自动计算导入顺序：存在缺失父项或循环时列出
   问题键与类型并**阻止顺序导出**（第 3 区的合并 CSV 导出不受影响）；
   层级有效时展示排序后的键序（父先子后，每步从当前可输出的行里选
   原合并 CSV 行序最早者），点击「下载顺序 CSV」得到 `import-order.csv`
   （沿用基准表头与原单元格值，仅行序重排）。改动裁决或父键列后自动重新计算。
7. **疑似唯一键变更核对（可选）**：有些「删除 + 新增」其实可能是同一行改了唯一键。
   冲突全部裁决后，第 7 区自动从本轮基准与最终结果提取**消失键**（基准有、最终结果没有）
   与**新增键**（最终结果有、基准没有）——两组各限 12 个，任一组超限都会明确提示
   而不给出配对。勾选至少一个**非键比较列**（默认全选），并设置 0 至比较列数的整数
   **差异上限**：逐格按原字符串比较，以不同格数为代价，超限的行对不能配对。
   服务端求允许交叉的一对一配对（先让配对数最多、再让总代价最小），并对每个消失键
   列出所有最优方案中可能对应的新键与是否可能未配对；只有所有最优方案都配向同一新键
   时才标为**稳定候选**——候选只是核对线索，不能认定为真实改名。
   页面展示最优配对数、总代价、稳定候选数与候选代价，可下载 `key-change-check.json`；
   任一组为空时返回空配对并列出全部未配对旧键。核对不改变任何数据与裁决，
   改动裁决或核对参数后自动重算，有未决冲突或轮次失效时清除旧结论。
8. **最小决定列发现（可选）**：想知道哪些列组合能决定某个目标列（函数依赖）时，
   冲突全部裁决后在第 8 区选择一个**非键目标列**，并勾选 **1～10 个互异候选列**
   （候选不得包含目标列或唯一键列，选满 10 个后其余自动禁用）。服务端从本轮模型与
   当前裁决取得**最终保留行**——最多 **300** 行，超限明确提示而不给结论；无保留行时
   提示无数据。逐格**按原字符串**比较（不裁剪空白，**空字符串也是值**）：任意两行在
   组合各列上相同就必有相同目标值时，该组合成立。服务端枚举**所有**成立且任何真子集
   均不成立的组合（**不能只找列数最少者**，不同列数的最小组合可以并存）；
   目标列在全部保留行中恒定时**只返回空组合**。每个非空最小组合**逐列移除**，
   附一对在剩余列上相同、目标值却不同的行作为**失效证明**（行键与双方目标值，
   行对按最终行序取字典序最早者）；不存在任何成立组合时给出**全候选列相同而目标
   不同的反例行对**（同样取字典序最早）。页面按**列数、基准表头列序**排列组合，
   可下载 `determinants.json`；结论注明**仅适用于当前数据**，裁决或选列变化后自动
   重算，有未决冲突或轮次失效时清除旧结果，不改变任何数据、裁决与 CSV 导出。
9. **合并金额尾差分摊（可选）**：需要把各组合并金额四舍五入到分入账、又要保证
   每组各行分摊额之和精确等于组总额时，在第 9 区选择互异的**分组列**与**金额列**
   （分组列可含空串，空串也成组）。金额以**元**计，只接受**非负、无指数、最多四位
   小数**的十进制字符串；**空值或非法值**会逐行指出**最终 CSV 行号**并**拒绝整次
   计算**（修正数据后自动重算）。服务端按本轮模型与当前裁决取得最终保留行，按分组列
   **原字符串**分组，各组**精确求和**后**四舍五入到分**；每行先**向下取整到分**，
   再把差额按**不足一分的余数降序**、同余数按**最终行序**逐分分配（各 +1 分）。
   页面展示每组精确合计、四舍五入总额、尾差分配行与逐行分摊额；点击
   「下载分摊 CSV」得到 `allocated.csv`——沿用基准表头与原单元格值、按**原行序**
   追加**分摊金额**列。原表头已有「分摊金额」同名列时明确报错（不会覆盖原列）；
   **无保留行时文件只含追加后的新表头**。服务端只从本轮模型与裁决取数（浏览器回传的
   行值一律忽略），裁决或选列变化后自动重算，有未决冲突或轮次失效时清除旧结果，
   原合并 CSV（`merged.csv`）导出不受任何影响。
10. **下载结果**：点击「下载合并 CSV」，得到 `merged.csv`
    （UTF-8 带 BOM，Excel 直接打开不乱码；表头顺序与基准一致）。
    账本、层级核验与导入顺序由服务端按本轮保存的模型与裁决实时计算，
    逐格取值与该 CSV 完全一致。

> 上传成功后，三份文件的解析结果保存在服务端本轮会话中，前端只需回传本轮标识。
> 若间隔过久（默认 1 小时）或服务已重启，继续比对 / 导出时页面会提示
> 「本轮上传数据不存在或已过期」，重新上传三份文件即可。

## 合并规则

以基准为共同祖先，按唯一键逐行、逐单元格比较：

### 自动采纳（无需人工介入）

| 场景 | 结果 |
| --- | --- |
| 只有一侧修改某单元格 | 采纳该侧修改 |
| 两侧把同一格改成**相同**的值 | 只采纳一次 |
| 只有一侧删除整行（另一侧未改） | 删除该行 |
| 两侧都删除整行 | 删除该行 |
| 只有一侧新增整行 | 采纳新增 |
| 两侧都新增且内容**完全一致** | 新增一次 |

### 产生冲突（必须人工解决）

| 冲突 | 形式 | 解决方式 |
| --- | --- | --- |
| 同一格两侧改成**不同值** | 单元格冲突 | 取本地 / 取远端 / 手填 |
| 一侧**删除**整行、另一侧**修改**该行 | 行级冲突 | 保留行（采纳修改）/ 删除行 |
| 两侧都**新增**同一键但**内容不同** | 行级 + 单元格冲突 | 先选保留/删除；保留时逐格取本地/远端/手填 |

### 上传校验（拒绝并标明文件与行号）

- 空键值、文件内重复键：给出 `<文件名> 第 N 行`；
- 表头不一致（列数、列名或顺序差异）：标明文件及具体是第几列；
- CSV 语法错误（引号未闭合、列数不符）：标明物理行号；
- 非 UTF-8 编码：提示另存为 UTF-8 后重试。

> 行号指文件中的物理行号（含表头，表头为第 1 行），带引号跨行的字段按其起始行计算。

## 来源账本（merge provenance ledger）

账本回答一个问题：**合并结果里的每一个格子，值是从哪来的？**

- **逐格归因**：未改动的值记 `基准`；单侧修改记 `本地` / `远端`；两侧改成相同的值记
  `两侧相同`；冲突手填的值记 `人工填写`。单侧新增整行记对应侧，两侧同值新增整行记两侧；
  同键异值新增、删除/修改冲突在裁决后同样按上述规则逐格归因。
- **行号可溯**：每个来源都标注原文件物理行号（如 `本地 第3行`）；人工手填的值没有来源行号，
  账本中记 `null`，不虚构行号。
- **删除另列**：被删除的键（单侧删除、两侧都删除、行级冲突裁决删除）不混入输出行，
  在账本末尾的 `deleted` 列表中单独给出删除原因与相关行号。
- **与导出一致**：账本与 `merged.csv` 由服务端用同一份模型、同一套裁决逻辑计算，
  行序与逐格取值完全一致；请求体里夹带的任何行数据都会被忽略。
- **JSON 结构**：`rows[].cells[]` 为 `{ column, value, source, sourceText, lines }`，
  `deleted[]` 为 `{ key, reason, reasonText, lines }`，并附 `sourceLegend` /
  `deleteReasonLegend` 图例，可直接存档或交给其他工具复核。

## 父子层级核验（hierarchy check）

合并结果如果承载父子层级（商品分类、组织架构、菜单树……），父键悬空或成环往往会让
下游系统出错。核验回答一个问题：**合并结果里的每一行，它的父键还指得通吗？**

- **在最终行上核验**：冲突全部裁决后，服务端按本轮保存的模型与当前裁决算出最终保留行
  （与 CSV 导出、来源账本同一套 `resolveRowProvenance` 计算），以最终唯一键建立索引；
  有未决冲突时拒绝给出完整结论（HTTP 409），页面只显示待解决提示。
- **父键列自选**：从现有表头中选择父键列，唯一键列不可作为父键列（服务端同样校验，
  违反返回 400）。
- **匹配规则**：空字符串父键视为根，不参与问题判定；其余父键按原字符串精确匹配，
  不裁剪空白、不做任何归一化。
- **两类问题**：
  - `missing-parent` 缺失父项：父键指向不存在或已被删除的键；
  - `cycle` 循环：父键指向自身（自环）或多行相互指向成环的**环上成员**；
    仅仅指向环的非环成员不报循环。
- **结果展示**：按最终 CSV 行序列出问题键、父键、类型与输出行号
  （最终 CSV 的物理行号，表头为第 1 行）；每次改动裁决后自动重新核验，
  点击「下载核验 JSON」可保存 `hierarchy-check.json` 存档或复核。
- **只提示，不改导出**：核验结果不影响 `merged.csv` 的内容，是否修复由你决定。

## 父子数据导入顺序（parent-first import order）

把合并结果导入下游系统（数据库、目录服务、菜单配置……）时，父子层级数据通常要求
**父行先于子行**写入，否则子行的父键会悬空。本功能回答一个问题：
**这份合并结果应该按什么顺序导入？**

- **同一套最终行**：冲突全部裁决后，服务端按本轮保存的模型与当前裁决算出最终保留行
  （与 CSV 导出、来源账本、层级核验同一套 `resolveRowProvenance` / `analyzeHierarchy`
  计算）；父键列沿用层级核验区域的选择，有未决冲突时拒绝计算（HTTP 409），
  轮次过期同样提示重新上传（HTTP 404）。
- **先核验再排序**：空父键视为根，其余父键按原字符串精确匹配最终唯一键。
  存在**缺失父项**或**循环**时，页面列出问题键、父键、类型与输出行号，
  并**阻止顺序导出**（`/api/order/export` 返回 409 且同样列出问题）；
  第 3 区的合并 CSV 导出（`/api/export`）不受任何影响，仍可使用。
- **父先子后排序**：层级有效时，每步从当前可输出的行（父行已输出，或本身就是根）里
  选**原合并 CSV 行序最早**的一行，直到全部输出——同层行的相对顺序尽量保持原行序。
- **页面展示键序**：排序后的键序（导入顺序、唯一键、父键、原合并 CSV 行号）直接展示；
  每次改动裁决或父键列后自动重新计算。
- **下载顺序 CSV**：`import-order.csv`（UTF-8 带 BOM），沿用基准表头顺序与原单元格值，
  仅行序重排为父先子后；内容由服务端按当前裁决实时生成，与页面展示的键序一致。
- **JSON 结构**（`/api/order` 返回的 `order`）：`{ version, generatedAt, keyColumn,
  parentColumn, rowCount, issueCount, valid, typeLegend, issues, keys }`；
  `issues[]` 同层级核验（`{ key, parentKey, type, typeText, line }`）；
  `keys[]` 仅 `valid=true` 时给出，为 `{ key, parentKey, line, mergedLine }`
  （`line` 为顺序 CSV 行号，`mergedLine` 为原合并 CSV 行号，表头均为第 1 行），
  层级有问题时 `keys` 为 `null`。

## 跨轮冲突裁决方案（conflict resolution plan）

同样的三方比对要重复做很多轮（比如远端分支更新后重新合并）时，上一轮已经仔细裁决过的
冲突不必再点一遍。方案回答一个问题：**这一轮的冲突行，和上一轮我裁决过的是不是同一行？
如果是，直接沿用上次的裁决。**

- **只含完整裁决**：方案只收集冲突行，且每行的冲突（行级去留、各冲突列取值，含手填值）
  必须全部裁决；还有未决冲突时服务端拒绝导出（HTTP 409）。
- **按内容识别，不按位置**：每行记录唯一键列、完整表头、基准 / 本地 / 远端三方的
  **存在状态**与**各列原值**、冲突类型（`row-delete-modify` / `row-add-divergent` +
  冲突列下标）与裁决。方案**不含 roundId、不含原文件行号**，因此重新上传后行序调整、
  插入或删除无关行、物理行号整体变化，都不影响匹配。
- **全等才套用**：服务端用本轮重新算出的模型逐行核对——键列与表头（列名、列数、顺序）
  完全一致，且该行三方存在状态、三方各列原值（字符串精确比较，不裁剪空白）、冲突类型
  完全相同，才整行套用方案裁决；任一不同则该行跳过，并给出原因：
  `key-not-found`（本轮无此键）、`not-conflict`（本轮该行已自动合并不是冲突）、
  `presence-mismatch`（三方存在状态不同）、`values-mismatch`（原值不同）、
  `conflict-mismatch`（冲突类型 / 冲突列不同）。
- **人工优先**：**当前行已有任一裁决时整行跳过**（`already-decided`），
  方案绝不会覆盖你本轮已经做过的操作；各行互不影响，可以只套用其中一部分。
- **格式错误零改动**：方案不是合法 JSON、结构不合法、键列或表头与本轮不一致时返回 400，
  在套用任何一行之前拒绝，**不改动任何已有裁决**。
- **套用即本轮裁决**：导入成功后返回合并后的完整裁决，CSV 导出、来源账本、层级核验
  全部读取它；未匹配上的冲突继续在页面上手动解决，之后可再次导入或随时改判。
- **JSON 结构**（`version: 1`，下载文件名 `conflict-plan.json`）：
  `{ kind, version, generatedAt, keyColumn, headers, rows[] }`，每行
  `{ key, presence:{base,local,remote}, values:{base: string[]|null, local, remote},
  conflicts:{ row: <行级冲突类型>|null, cells: number[] },
  decision:{ row: 'keep'|'delete'|null, cells:[{ column, choice, value? }] } }`，
  `column` / `cells[]` 均为以 0 开始的列下标。

## 疑似唯一键变更核对（key-change check）

合并结果里「消失的旧键 + 出现的新键」有时其实是同一行改了唯一键（改名、换编码规则……）。
本功能回答一个问题：**每个消失的键，最可能对应哪个新键？**

- **两组键**：冲突全部裁决后，服务端按本轮保存的模型与当前裁决算出最终保留行
  （与 CSV 导出、来源账本同一套 `resolveRowProvenance` 计算），从本轮基准与最终结果提取
  **消失键**（基准有、最终结果没有，按基准行序，附基准物理行号）与
  **新增键**（最终结果有、基准没有，按最终 CSV 行序）。两组各限 **12** 个，
  任一组超限时返回 409（`stage=limit`，附两组数量）并明确提示，不给出配对。
- **比较参数**：用户选择至少一个**非键比较列**（唯一键列不可选，服务端同样校验，
  违反返回 400），并设置 0 至比较列数的整数**差异上限**。旧键的基准行与新键的最终行
  逐格**按原字符串**比较（不裁剪空白、不做归一化），以不同格数为代价，
  代价超过上限的行对不能配对。
- **最优配对**：求允许交叉的一对一配对——**先让配对数最多，再让总代价最小**
  （字典序目标）。组大小 ≤ 12，服务端用子集 DP 精确求解，并给出一组最优配对。
- **逐键可能性**：对每个旧键，列出**所有最优方案**中可能对应的新键（含各自代价），
  以及是否可能未配对；只有所有最优方案都把它配向**同一新键**时才标为**稳定候选**。
  候选只是核对线索，**不能认定为真实改名**（结果 JSON 中也带有同样的提示）。
- **页面与下载**：展示最优配对数、总代价、稳定候选数与候选代价（候选配对代价之和），
  逐旧键列出可能的新键与结论，并列出所有最优方案中都不配对的新键；
  可下载 `key-change-check.json` 存档复核。**任一组为空时返回空配对**，
  并列出全部未配对旧键。
- **只读核对**：核对不改动任何数据与裁决（CSV 导出、账本、层级核验完全不受影响）；
  改动裁决或核对参数后自动重算，有未决冲突（409）或轮次失效（404）时清除旧结论。
- **JSON 结构**（`/api/keycheck` 返回的 `check`）：`{ version, generatedAt, keyColumn,
  columns, maxDiff, limit, oldCount, newCount, pairCount, totalCost, candidateCount,
  candidateCost, pairs: [{ oldKey, newKey, cost }], oldKeys: [{ key, line,
  possibleNewKeys: [{ newKey, cost }], canBeUnpaired, stable, stableNewKey, stableCost }],
  newKeys: [{ key, line, pairable }], unpairedOldKeys, unpairedNewKeys, disclaimer }`；
  `oldKeys[].line` 为基准物理行号，`newKeys[].line` 为最终 CSV 行号（表头为第 1 行）。

## 最小决定列发现（minimal determining columns）

想知道「哪些列组合能决定某一列」（数据库里的函数依赖 X → Y）时，本功能回答一个问题：
**在当前合并结果里，目标列由哪些最小的候选列组合决定？**

- **在最终行上发现**：冲突全部裁决后，服务端按本轮保存的模型与当前裁决算出最终保留行
  （与 CSV 导出、来源账本、层级核验、键变更核对同一套 `resolveRowProvenance` 计算）。
  最终保留行最多 **300** 行，超出时返回 409（`stage=limit`，附实际行数）并明确提示，
  不给出结论；**无保留行**时返回 200 且 `noData=true`，页面提示无数据；
  有未决冲突时拒绝给出结论（409），轮次过期同样 404。
- **选列约束**：目标列必须在表头中且**不能是唯一键列**；候选列必须为 **1～10 个互异**
  列名，各自在表头中，且**不得包含目标列或唯一键列**（服务端同样校验，违反返回 400）。
- **成立判定**：任意两行在组合各列上的取值**按原字符串精确比较**（不裁剪空白、不做
  归一化，**空字符串 `""` 也是一个普通值**）全部相同时，目标列取值也必须相同。
- **枚举全部最小组合**：列出所有「自身成立、且任何真子集都不成立」的组合——
  **不只列数最少者**，不同列数的最小组合可以同时存在（如 `{a}` 与 `{b,c}` 并存）；
  目标列在全部保留行中**恒定**时，空组合（不需要任何列）即成立，此时**只返回空组合**。
- **逐列移除的失效证明**：每个非空最小组合对其中每一列给出一个证明：删去该列后的
  真子集不成立，附一对行——两行在剩余列上取值相同、**目标值不同**，含双方行键
  与目标值（及最终 CSV 行号，表头为第 1 行）；行对按最终行序取**字典序最早**者
  （第一行行号最小，并列时第二行行号最小）。
- **无组合时的反例**：连全部候选列都不能决定目标列时，不存在任何成立组合，
  返回一对在**全部候选列上相同而目标值不同**的行（附共享的候选列值，同样取字典序
  最早行对）作为反例。
- **页面与下载**：组合按**列数升序、再按基准表头列序字典序**排列；可下载
  `determinants.json`，其中带有 `disclaimer`，注明结论**仅适用于当前数据**
  （裁决或选列变化、数据增减后需重新计算）。
- **只读发现**：不改动任何数据与裁决（CSV 导出、账本、层级核验完全不受影响）；
  改动裁决或选列后自动重算，有未决冲突（409）或轮次失效（404）时清除旧结论。
- **JSON 结构**（`/api/determinants` 返回的 `result`）：
  `{ version, generatedAt, keyColumn, targetColumn, candidateColumns, limit, rowCount,
  noData, constantTarget, combinationCount, combinations: [{ columnCount, columns,
  witnesses: [{ removedColumn, row1: {key, line, targetValue}, row2 }] }],
  counterexample: { row1, row2, values: [{column, value}] } | null, disclaimer }`；
  目标恒定时 `combinations` 仅含一个 `columnCount=0`、`columns=[]`、`witnesses=[]` 的
  空组合；无组合时 `combinations=[]` 且 `counterexample` 非空；`line` 为最终 CSV
  物理行号（表头为第 1 行，首行数据为第 2 行）。

## 合并金额尾差分摊（cent rounding-difference allocation）

把各组合并金额按分入账时，逐行四舍五入会让组内各行之和与组总额的四舍五入结果相差
几分钱。本功能回答一个问题：**尾差这几分钱，应该加给组里的哪几行，才能让逐行金额
之和精确等于组总额？**

- **在最终行上分摊**：冲突全部裁决后，服务端按本轮保存的模型与当前裁决算出最终保留行
  （与 CSV 导出、来源账本及其他分析模块同一套 `resolveRowProvenance` 计算，行序、
  逐格取值完全一致）。有未决冲突时拒绝计算（HTTP 409，`stage=unresolved`），
  轮次过期同样 404。
- **选列约束**：分组列与金额列都必须在表头中且**互异**（分组列允许是唯一键列；
  违反返回 400）。分组按分组列的**原字符串**精确比较，不裁剪空白、不做归一化，
  **空字符串 `""` 也是一个普通组**。
- **金额格式**：金额以**元**计，只接受**非负、无指数、最多四位小数**的十进制字符串
  （正则 `^(?:0|[1-9]\d*)(?:\.\d{1,4})?$`，因此拒绝空串、空白、正负号、`1e3`、
  `.5`、`1.`、前导零 `01`、五位及以上小数）。**空值或任一非法值都会逐行指出最终
  CSV 行号**（含行键与原始值）并返回 409（`stage=amount`），**拒绝整次计算**，
  不产出任何分摊结果。
- **精确求和 + 四舍五入到分**：金额先解析为万分之一元（`1e-4` 元）的 BigInt 整数，
  全程整数运算、不经过浮点；组总额按整数精确求和后**四舍五入到分（半值向上）**，
  即 `round(sum/100) = (sum + 50) / 100`（整数除法）。
- **逐行取整与尾差分配**：每行先**向下取整到分**（`floor(v/100)`）；组总额四舍五入
  与各行取整之和的差额 D（单位：分，恒有 `0 ≤ D ≤ 行数`）按每行**原金额不足一分的
  余数**（`v mod 100`，单位为万分之一元）**降序**逐分分配，余数相同的行按**最终
  CSV 行序**靠前者优先——余数排名前 D 行各多得 1 分。因此每组各行分摊额之和
  **精确等于**该组四舍五入到分的总额。
- **页面展示**：按组首次出现顺序列出每组的行数、精确合计（元，最多四位小数）、
  四舍五入到分的总额与尾差分配行；组内按最终 CSV 行序列出每行原金额、向下取整额、
  不足一分余数、是否多得 1 分与最终分摊金额。
- **下载分摊 CSV**：`allocated.csv`（UTF-8 带 BOM），沿用基准表头与原单元格值、
  保持**原合并 CSV 行序**，仅在末尾追加固定名为**分摊金额**的列（值为固定两位小数
  的元字符串）。**原表头已有同名列时返回 400 明确报错**，绝不覆盖原列；
  **无保留行时文件只包含追加后的新表头**。原 `/api/export` 的 `merged.csv`
  不受任何影响。
- **只读且只认本轮数据**：服务端只从本轮模型与请求中的裁决取数，请求体里夹带的任何
  行值都会被忽略；裁决或选列变化后自动重算，有未决冲突或轮次失效时清除旧结果；
  分摊不改动任何数据、裁决与原合并 CSV。
- **JSON 结构**（`/api/allocation` 返回的 `allocation`）：
  `{ version, generatedAt, keyColumn, groupColumn, amountColumn, appendedHeader,
  rowCount, noData, groups: [{ groupValue, rowCount, exactTotalText, roundedTotalText,
  differenceCents, allocationOrder: number[], rows: [{ key, line, amountRaw, floorText,
  remainder, remainderCentsText, gotDifference, allocatedText }] }] }`；
  `line` 为最终 CSV 物理行号（表头为第 1 行）；无保留行时 `noData=true`、
  `groups=[]`、`rowCount=0`。

## 示例数据覆盖的场景

点击首页「载入示例数据」，键列选择 `id`，可看到：

- `K1` 仅本地单侧修改；`K8` 仅远端单侧修改 → 自动采纳
- `K2` 两侧相同修改 → 只采纳一次
- `K7`、`K4` 单侧修改不同的列/行 → 各自自动采纳
- `K5` 仅远端删除 → 自动删除
- `K3` 本地修改 vs 远端删除 → 行级冲突（保留 / 删除）
- `K6` 同一格两侧改成不同值 → 单元格冲突
- `K9` 三方一致 → 不变
- `L1` / `R1` 单侧新增 → 自动新增
- `X1` 两侧新增且相同 → 自动新增；`X2` 同键新增但内容不同 → 行级冲突，保留后逐格裁决
- 示例另含 `parent` 列，可体验父子层级核验（裁决完全部冲突后选择父键列 `parent`）：
  `K6` 指向已删除的 `K5`、`R1` 指向不存在的键 → 缺失父项；`K7`/`K8` 相互成环、
  `X2` 保留时指向自身 → 循环；`K9` 仅指向环而非环成员 → 不报循环
- 由于示例层级存在缺失父项与循环，第 6 区会列出问题并**阻止顺序导出**
  （合并 CSV 导出不受影响）；换成层级有效的数据即可看到排序后的键序与顺序 CSV 下载
- 第 7 区可体验疑似唯一键变更核对：裁决完全部冲突后，`K5`（以及裁决删除时的 `K3`）
  进入消失键，`L1` / `R1` / `X1`（以及裁决保留时的 `X2`）进入新增键；
  调整比较列与差异上限可以看到不同的配对数、总代价与候选结论
- 第 8 区可体验最小决定列发现：选择非键目标列（如 `note`）并勾选若干候选列
  （如 `name` / `city` / `parent`），可看到最小组合、逐列移除的失效证明行对或反例；
  切换目标列 / 候选列、调整裁决后结论自动重算（示例数据也包含空父键等空字符串取值，
  空串与其他值一样按原字符串参与比较）
- 第 9 区可体验合并金额尾差分摊：示例含 `amount` 列（元，最多四位小数）。选择分组列
  `note`、金额列 `amount`，裁决完全部冲突后可看到「备注」组多行精确求和后四舍五入
  到分的尾差，按不足一分余数降序逐分分配（标「+1 分」），逐行分摊额之和精确等于
  组总额；分组列选 `parent` 还可看到空串分组（根行）。下载得到追加「分摊金额」列的
  `allocated.csv`，原合并 CSV 导出不变

## API 简介

| 接口 | 说明 |
| --- | --- |
| `POST /api/upload` | multipart 上传三份 CSV，做 UTF-8 / 语法 / 表头一致性校验；服务端保存本轮解析结果，返回 `roundId` |
| `POST /api/merge` | 只提交 `{ roundId, keyColumn }`，服务端取回本轮数据校验空键与重复键，返回三方合并模型与冲突清单（模型同样留在服务端） |
| `POST /api/export` | 只提交 `{ roundId, decisions }`；标识无效 / 过期返回 404，有未解决冲突返回 409，否则返回 `merged.csv` |
| `POST /api/ledger` | 只提交 `{ roundId, decisions }`；返回合并结果来源账本 JSON（逐格最终值 + 取值来源 + 原文件行号，删除键单独列出原因）。同样 404 / 409；与导出共用服务端模型与裁决，逐格取值一致 |
| `POST /api/hierarchy` | 只提交 `{ roundId, decisions, parentColumn }`；父键列必须在表头中且不能是唯一键列（否则 400）。返回父子层级核验 JSON（缺失父项 / 循环，按最终 CSV 行序，含输出行号）。同样 404 / 409；与导出共用服务端模型与裁决，只提示不改变导出 |
| `POST /api/order` | 只提交 `{ roundId, decisions, parentColumn }`；父键列校验同层级核验（400）。返回父子数据导入顺序 JSON：存在缺失父项 / 循环时 `valid=false` 并列出问题键与类型；层级有效时 `valid=true` 并给出父先子后的排序键序（每步取当前可输出行中原合并 CSV 行序最早者）。同样 404 / 409 |
| `POST /api/order/export` | 参数同上；仅层级有效时返回 `import-order.csv`（沿用基准表头与原单元格值，父先子后行序）。存在缺失父项 / 循环时返回 409 并列出问题键与类型（阻止顺序导出）；未决冲突同样 409；不影响 `/api/export` 合并 CSV 导出 |
| `POST /api/plan/export` | 只提交 `{ roundId, decisions }`；返回跨轮冲突裁决方案 JSON（仅已完整裁决的冲突行：键列、表头、三方存在状态与原值、冲突类型、裁决含手填值；不含 roundId 与行号）。有未决冲突返回 409 |
| `POST /api/plan/import` | 提交 `{ roundId, decisions, plan }`；服务端用本轮模型按唯一键逐行核对，键列 / 表头 / 三方原值 / 冲突类型完全相同才整行套用；已有任一裁决的行整行跳过。返回合并后的完整 `decisions` 与套用 / 跳过报告（含中文原因）。方案格式错误、键列或表头不一致返回 400 且不改动任何裁决 |
| `POST /api/keycheck` | 只提交 `{ roundId, decisions, columns, maxDiff }`；`columns` 为至少一个非键比较列，`maxDiff` 为 0 至比较列数的整数（违反返回 400）。返回疑似唯一键变更核对 JSON：消失键 / 新增键（两组各限 12 个，超限返回 409 `stage=limit` 并附两组数量）、最优配对数与总代价、一组最优配对、逐旧键的所有最优方案可能新键与是否可能未配对、稳定候选与候选代价。任一组为空时返回空配对并列出未配对旧键。同样 404 / 409（未决冲突）；只读核对，不改动任何数据与裁决 |
| `POST /api/determinants` | 只提交 `{ roundId, decisions, targetColumn, candidates }`；`targetColumn` 为非键目标列，`candidates` 为 1～10 个互异候选列且不含目标列与唯一键列（违反返回 400）。返回最小决定列发现 JSON：枚举所有成立且任何真子集均不成立的组合（按列数 / 基准表头列序），非空组合附逐列移除的字典序最早失效行对（行键与目标值）；目标恒定时只返回空组合；无保留行时 `noData=true`；无组合时给出全候选列相同而目标不同的反例。最终保留行超过 300 行返回 409 `stage=limit` 并附行数；同样 404 / 409（未决冲突）；只读发现，不改动任何数据与裁决及 CSV 导出 |
| `POST /api/allocation` | 只提交 `{ roundId, decisions, groupColumn, amountColumn }`；两列必须在表头中且互异（分组列可含空串，违反返回 400）。返回合并金额尾差分摊 JSON：按分组列原字符串分组，各组 BigInt 精确求和后四舍五入到分，每行先向下取整到分，差额按不足一分余数降序、同余数按最终行序逐分分配；金额只接受非负无指数最多四位小数字符串，空值 / 非法值逐行指出最终 CSV 行号并返回 409 `stage=amount` 拒绝整次计算；原表头已有「分摊金额」同名列返回 400；无保留行时 `noData=true`。同样 404 / 409（未决冲突）；只读，不改动任何数据、裁决与原合并 CSV |
| `POST /api/allocation/export` | 参数同上；返回按原合并 CSV 行序追加「分摊金额」列的 `allocated.csv`（沿用基准表头与原单元格值；无保留行时只输出新表头）。选列非法 / 原表头撞名返回 400，未决冲突 409 `stage=unresolved`，非法金额 409 `stage=amount`（附最终 CSV 行号）；不影响 `/api/export` 合并 CSV 导出 |
| `GET /api/health` | 健康检查 |

## 说明与限制

- 单文件大小上限 20MB（可在 `server.js` 中调整 multer 限制）；
- 三份接近上限的大文件，其解析结果与合并模型不再随合并 / 导出请求反复传输，
  而是在上传后保存在**服务端内存**中：前端只回传本轮标识 `roundId`、键列与冲突决策，
  因此不会触发 JSON 请求体的 20MB 上限；
- `roundId` 为服务端生成的随机标识，1 小时无后续请求自动过期（可通过环境变量
  `ROUND_TTL_MS` 调整），标识无效或过期时接口明确返回 404，绝不会误用其他轮数据，
  前端会提示重新上传；服务重启后所有本轮数据同样清空；
- 文件只保存在内存中处理，不写入磁盘；
- 键列值按字符串精确比较，比较前后均不做空白裁剪；
- 仅要求三份文件表头一致；数据行列数异常会在上传阶段被拒绝。
